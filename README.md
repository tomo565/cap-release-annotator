# キャップ リリース窓の教示

test 19本 × リリース−3〜+10 の 14コマ、合計 266コマ に人が正解位置を打つための画面。

GitHub Pages に置いた静的ファイルと Supabase だけで動く。**PCの電源が入っていなくても、
Android Chrome と iPad Safari から使える。** 同じ Supabase を見るので、端末をまたいで続きから再開できる。

## 中身

| | |
|---|---|
| `index.html` | 画面本体。これ1枚で動く |
| `config.js` | Supabase の接続先。ここだけ書き換える |
| `data/tasks.json` | 打つ順番、コマ番号、切り出しの左上座標 |
| `img/` | 原寸のまま 640×640 を切り出した画像。266枚。ここを見て打つ |
| `ov/` | 画面全体を1/3にした参考画像。266枚 |
| `schema.sql` | Supabase に一度だけ流すテーブル定義 |

切り出しを 640 にした根拠は、リリース−3〜+10 の間に蓋が動く量が実測で最大 114px だから。
中心を人が打ったリリース点に置けば ±320px の余裕がある。原寸で切っているので 5px の蓋が潰れない。

## 正解の扱い

- 打った瞬間は**下書き**（黄色）。`確定して次へ` を押して初めて `confirmed_by_human = true` になる。
- 書き出しに入るのは `confirmed_by_human = true` の行だけ。
- 参考予測（`H`／メニューから切替）は**表示だけ**。既定は非表示。押しても正解にはならない。
- 既存の軌跡も YOLO の予測も、自動で正解に入ることはない。
- 完全に隠れているコマは位置なしで確定できる。見えない物を推測させない。
  これらは位置の評価から外し、遮蔽区間の件数として別に数える。

## 使い方

1. 画面を開く。初回だけ Supabase の URL と anon key、名前を入れる（`config.js` を埋めてあれば名前だけ）
2. 上に `動画ID` `リリース±N` `コマ番号` が常に出ている
3. 原寸画像を**タップ**して蓋の中心を打つ
4. 右（狭い画面では下）の8倍表示を**ドラッグ**して微調整。矢印ボタンは1px刻み
5. 見え方を選ぶ（見える／一部隠れ／完全に隠れ／判断できない）
6. `確定して次へ`
7. 迷ったら `見送り`、打ち直すなら `取消`

通信が切れても打点は端末に残り、復帰したときにまとめて送られる。
下の帯に `未送信 N 件` と出ていれば、まだ送れていないだけで失われてはいない。

蓋が切り出しの外に出ていたら、タグをタップすると全体図に切り替わる。全体図は参考のみで打てない。
外に出ていた場合は `判断できない` にして、あとで切り出しを広げて作り直す。

## 打ち終わったら

メニューから `JSONで書き出す` か `CSVで書き出す`。落としたファイルを PC に移して取り込む。

```
python import_anno.py annotations.json
```

Supabase から直に引くこともできる。

```
python import_anno.py --url https://xxxx.supabase.co --key eyJ...
```

どちらも `truth_release.json` を作る。これは `truth.json` と同じ形なので、そのまま評価に使える。

```
python evalcap.py --model C_best.pt --tag C_rel --truth truth_release.json --input raw --scope roi
```
